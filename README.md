### 哪一档是分水岭

**VM-0.5 是试水档。** 5GB 磁盘装完 Debian 只剩 3GB 出头，MySQL 加 WordPress 就满了。它的合理用途是 WireGuard 中继、监控探针、跑个定时脚本，或者纯粹花 $2.99 验证一下 KT 线路到你家宽带的表现。

**VM-1（$5.99）才够建站。** 20GB 磁盘放系统和三四个小站有富余，2GB 内存跑 LNMP 不至于天天 OOM。绝大多数个人博客、外贸展示站、轻量 API 停在这一档。

**VM-1.5 是这张表里性价比最突出的一档。** 从 VM-1 加 $0.96 就多一个核，流量从 1TB 涨到 1.5TB。跑 PHP、Node 这类吃单核性能的应用，加核比加内存有用，这不到一美元比 VM-1 升 VM-2（多 $6）划算得多。

**VM-2 起是给多站点和容器的。** 4GB 内存能同时跑 Docker 里的数据库、缓存和应用，30GB 磁盘装得下镜像。再往上，VM-4 和 VM-6 属于多站点托管、中型数据库、高并发 API 的区间，个人用户很少需要，16 核的 VM-12 和 VM-16 更是给批处理、渲染队列这类长任务准备的。

## 首尔机房能解决什么，什么情况下别买

需要首尔机器的场景其实很具体：网站或应用的用户就在韩国、项目要求韩国 IP 或韩国原生 IP、给韩国玩家搭游戏后端和中继、从韩国发起监控和可达性测试、对接只认韩国地区的账号和 API、或者拿它当东北亚的一个区域节点。

Evoxt 首尔走 KT（AS4766）。**KT 是韩国本土最大的固网运营商，但它不等于大陆优化线路**，这个区别决定了体验上限。

| 运营商 | 回程路径 | 测评延迟 |
| --- | --- | --- |
| 电信 | KT 直连中国电信 163 骨干（AS4134） | 40–50ms |
| 联通 | KT 直连 AS4837（联通 169） | 45–50ms |
| 移动 | KT → CMI → 日本东京 → 回国 | 略高，绕日本 |

三网都不是专线优化。电信和联通是直连，移动绕日本，延迟高一截但路径稳定。两个独立测评都提到同一个问题：**电信方向在晚高峰可能出现丢包**，移动侧在高峰期延迟也会抬升。如果你的用户主要是电信宽带、又对晚高峰敏感，这台机器需要先测再买。

另外几种情况，首尔不是答案：要的是中国大陆低延迟，香港的线路资源明显更强；想要更多供应商和线路档位可选，日本的选择比韩国多；项目需要台湾本地位置或台湾 IP，那就直接看台湾。首尔的价值在于地理位置和韩国 IP，不在于绕开大陆的网络瓶颈。

## 原生韩国 IP 与解锁能力，别信商家也先别信测评

公开测评拿到的结果是：Netflix 韩国区、YouTube Premium 韩国区、Amazon Prime Video 韩国区、ChatGPT、Google Gemini 韩国区、TikTok（美区）都能解锁，Disney+ 和 Reddit 未解锁。IP 风险评分是 Scamalytics 0 分，属于干净段。

这些数据只能当参考。第三方平台的风控规则每周都在变，同一段 IP 上个月能开 Netflix，这个月可能就被标记。**唯一可靠的办法是自己花十分钟测一遍。**

**下单后的十分钟自测流程：**

1. 开一台最低配（VM-0.5 就够），用 `curl ipinfo.io` 和 `curl cip.cc` 两个来源确认 IP 归属地，两边结果不一致说明是广播 IP。
2. `traceroute` 到你家宽带的公网 IP，看回程是从 KT 直接回国，还是绕了日本、新加坡。绕路就说明这条线对你不是直连。
3. 在机器上跑目标平台的检测：Netflix 用 `curl -I https://www.netflix.com/title/80018499` 看是否返回 302，ChatGPT 直接打开网页看有没有地区限制提示。
4. **等到晚上八九点再测一次延迟和丢包**，白天的数据没有参考价值。

四步都过了再续费，任何一步不过就换。这也是为什么第一台别直接买年付。
